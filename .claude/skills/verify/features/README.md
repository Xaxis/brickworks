# Brickworks feature map

`../features.json` is generated by `featuremap` and never edited by hand. The
files here hold the recipes. Each declares the ids it covers in a
`<!-- covers: -->` line, and `featuremap check` fails when an id has no recipe or
a recipe covers an id that no longer exists.

Thirty-seven features in nine areas. The analyser sees Python, the API routes and
the main scene; **everything inside the Godot app is declared by hand** in
`../featuremap.config.json`, because `featuremap` has no GDScript or `.tscn`
reader. If you add a scene, a panel or a probe-worth-of-behaviour, add it there —
the generator will not find it for you.

## Preconditions

Every recipe assumes `tools/doctor.sh` exits 0: Godot 4.7, `vendor/ldraw`, a built
mesh cache in `assets/generated/`, and a display for anything that draws. Add
`--network` when the recipe talks to brickworks.diy.

Never driven from here:

- **Real email.** `POST /api/otp` with a valid address sends somebody a code
  through Resend. Every recipe below uses an address that fails validation.
- **The production account table.** `/api/admin` can change tiers. Read it (`GET`),
  never `POST` it as part of a check.
- **Money.** The assistant costs real tokens per run. The seven paid probes and
  `tools/design.py` are the only things here that spend, and a report has to say
  when it did.

## Proof rules

- Drive the path a person takes. A probe that drives the real scene through
  `Input.parse_input_event` counts; one that calls the builder directly proves the
  builder, not the control.
- **Godot exits 0 on a parse error.** A probe is a pass only when it exits 0 *and*
  printed no `FAIL`, `SCRIPT ERROR` or `Parse Error`. `tools/check.sh` enforces
  that; by hand, read the output.
- A recipe lists every entry point. Proving one does not prove the others.
- An unreachable entry point is reported with its missing precondition, not
  counted as verified.
- Two runs reporting the same wrong thing outrank one reading of the code. The
  stale-baseplate bug was reported twice and dismissed once before it was found.

## Areas

- [building](building.md): placing and removing bricks, dragging a selection box,
  editing a selection, undo, and the app window itself.
- [geometry](geometry.md): the 2 LDU lattice, sideways parts, sections carried at
  an angle, and whether a model would stand up.
- [parts](parts.md): searching 28k parts, the parts bin, and fetching a mesh that
  isn't in the pack.
- [model-io](model-io.md): saving, reopening, reading and writing `.ldr`, and the
  export command.
- [assistant](assistant.md): the design loop, the model and effort settings, and
  reference pictures.
- [view](view.md): the camera, the controls hint, build steps, mosaics, and the
  renders the assistant is shown.
- [web](web.md): the five API endpoints, the Vercel deploy, and the browser proof.
- [pipeline](pipeline.md): the Python tools that turn LDraw into the mesh cache,
  the catalogue, the web pack and the storage bucket.
- [mcp](mcp.md): the local port and the MCP server that let a Claude Code session
  build in the app instead of the app asking for an API key.

## Entry contract

Each area file has an H1, a one-line summary, a `<!-- covers: ids -->` line, then
exactly `## Sub-features`, `## How to reach it`, `## How to check it`,
`## Gotchas`. Keep it runnable without reading source.
